# 자체 변환 성공률 지표 정의

이 지표는 **시스템의 자동 시험 결과**다. 사람이 화면을 이해했는지, 실제 이용자에게 효과가 있었는지는 측정하지 않았다.

## 1. 실제 모델 변환 성공률 (M8, 모델 호출 필요)

- 표본 단위: (업종 3 × 프로필 3) 조합 9개 × 반복 N회. 반복마다 모델을 한 번 호출하고 재시도하지 않는다.
- 성공: 모델 응답이 JSON 객체로 읽히고(`parse`), 스키마를 통과하고, 불변 검증기의 모든 규칙을 통과하고, 프로필 제약(글씨 배율, 대비, 터치 영역, 단계 분할)을 지킨다. 이 판정은 브라우저가 쓰는 `adaptScreen`과 같은 코드가 한다.
- 실패 사유는 코드별로 센다(`parse`, `validation`의 오류 코드 등).
- 분자는 성공 표본 수, 분모는 호출 수다. 호출이 도구 오류로 응답을 못 받은 경우도 분모에 넣고 실패로 센다.
- 조합별 성공률과 전체 성공률을 모두 적는다. 표본 크기가 작아 신뢰구간이 넓음을 함께 적는다.
- 프롬프트와 모델, 실행 일시, 프롬프트 해시를 기록한다.

## 2. 검증기 거부율 (모델 없음)

`tools/local_metrics.mjs`가 계산한다.

- 기준 출력: 체험 모드 AI 출력 9개와 기준 변환기 출력 9개, 합 18개. 모두 통과해야 한다.
- 해로운 변조: 28가지 유형(예: 가격·차액 변경, 항목 삭제·추가, 수량·합계 변경, 확인 단계 이름·금액 변경, 원문 확인 끄기, 라벨 맞바꾸기, 이름 지우기, 숫자·한글 금액, 띄어 쓴 무료, 숨은 글자, 영어·한국어 지시문, HTML, 주소, 허용 외 키, 글씨·터치 영역 축소, 단계 순서, id 바꿔치기 등, 전체 목록은 `tools/local_metrics.mjs`)을 18개 기준 출력에 적용해 504개 변조 출력을 만든다. 거부 수 ÷ 504가 거부율이다.
- 무해한 변경: 이름 뒤 설명 덧붙임, 힌트 문구 교체, 더 큰 글씨, 직원 호출 문구 교체 4가지를 18개 기준 출력에 적용한 72개. 통과 수 ÷ 72가 허용률(오거부 확인)이다.

## 한계

- 변조 유형은 개발자가 만든 목록이다. 목록에 없는 공격은 이 숫자가 보장하지 않는다.
- 힌트·설명 문구의 의미(없는 성분을 단정하는 문구 등)는 검증하지 못한다.
- 표본이 작고 한 모델·한 프롬프트의 결과다. 다른 공급자(방문자 키 경로)의 성공률은 측정하지 않았다.
- 사용자 이해도와 효과는 측정하지 않았다.
